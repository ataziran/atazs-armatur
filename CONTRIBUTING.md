# Contributing

How to build, test and release atazs-armatur. How the program itself works is described in
[docs/how-it-works.md](docs/how-it-works.md).

## Requirements

- Go 1.27, the version on the `go` line in `go.mod`. It is the first Go release with
  Unicode 17.0.0, the version `width_table.go` is generated from.
- No other dependencies. The program uses the standard library only, and changes must keep it
  that way.

## Build

```bash
CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' .
```

This is the command the release uses. `-trimpath` removes local paths from the binary, and
`-ldflags='-s -w'` drops the symbol table and DWARF data. Version and commit are not passed in;
`--version` reads them from the build info Go embeds when building from a git checkout.

## Checks

Run before sending a change; CI runs the same on Linux, macOS and Windows:

```bash
gofmt -l .        # must print nothing
go vet ./...
go test ./...
```

## Golden tests

Rendering is covered by golden fixtures in `testdata/golden/`. Each case is a pair:

- `<case>.json` pins every input to the renderer.
- `<case>.out` is the expected output, compared byte for byte, escape sequences included.

Fields of `<case>.json`:

| Field      | Type   | Meaning                                                           |
| ---------- | ------ | ----------------------------------------------------------------- |
| `stdin`    | string | the payload, as Claude Code would send it                         |
| `cols`     | number | terminal width                                                    |
| `now`      | number | current time, Unix seconds                                        |
| `branch`   | string | git branch as it would be read from `.git/HEAD`                   |
| `getcwd`   | string | the process's working directory, used when the payload names none |
| `no_color` | bool   | behave as if `NO_COLOR` were set                                  |
| `mtime`    | number | transcript modification time, Unix seconds; omit for none         |
| `clock`    | string | idle mark glyph; defaults to `◷`                                  |
| `peer`     | string | peer name as it would be read from the session registry           |

The cases cover colour thresholds, half cells, truncation, wide characters, escapes in names,
peer names, waiting and idle rows, and malformed input.

New behaviour gets a new `.json` and `.out` pair. To write the `.out` files from the current
code:

```bash
go test -run TestGolden -update
```

This overwrites every `.out` file. Review the diff before committing; `cat -v` makes the escape
sequences readable.

The renderer (`render.go`) does not touch the system, which is what lets the goldens pin every
input as a value. Code that reads files, the environment or the terminal lives in `main.go`,
`git.go`, `peer.go` and the `term*.go` files; `git_test.go`, `peer_test.go`,
`peer_unix_test.go`, `session_test.go`, `term_test.go`, `width_test.go` and `version_test.go`
cover the parts outside the renderer.

## Line endings

`.gitattributes` checks out every file with LF on every OS, whatever `core.autocrlf` says, and
marks `testdata/golden/*.out` as `-text`, so git never converts their line endings. Both matter:
the goldens are compared byte for byte, and `gofmt` expects LF.

## Width table

`width_table.go` lists the East Asian Wide and Fullwidth ranges. It is generated by
`gen_width.go` from `EastAsianWidth.txt` for `unicode.Version` of the toolchain, so the wide ranges
agree with the standard library's zero-width tables. `TestWidthTableMatchesToolchain` fails when
the version in the file header differs from the toolchain's.

After moving to a Go release with a newer Unicode version:

```bash
go generate
```

This downloads `https://www.unicode.org/Public/<version>/ucd/EastAsianWidth.txt` and rewrites
`width_table.go`. Do not edit the file by hand.

## CI and releases

[`ci.yml`](.github/workflows/ci.yml) runs the checks above on Linux, macOS and Windows for every
push to `main` and every pull request, and `go vet` for every release target plus freebsd/amd64,
so each platform-specific file compiles.

A `v*` tag runs [`release.yml`](.github/workflows/release.yml). It tests, builds the six targets
with the command above, refuses a binary whose `go version -m` does not show the tag and
`vcs.modified=false`, writes `SHA256SUMS`, attests build provenance and creates the release.

Actions are pinned to commit SHAs, checkouts do not keep credentials, and only the `build` job,
which creates the release, can write to the repository.

## Reproducible builds

A release binary can be rebuilt byte for byte. The inputs that have to match:

- A clean clone checked out at the tag, with no untracked or modified files
- The build command above
- The same Go release, which `go version -m <binary>` prints
- The same `GOOS` and `GOARCH`

An untracked file anywhere in the clone makes Go stamp `vcs.modified=true`, so the example builds
to the parent directory and checks against a `SHA256SUMS` downloaded there, outside the clone.
Replace `v<version>` with the tag of the release you are checking:

```bash
git clone https://github.com/ataziran/atazs-armatur
cd atazs-armatur
git checkout v<version>
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags='-s -w' -o ../atazs-armatur-linux-amd64 .
cd ..
curl -fLO https://github.com/ataziran/atazs-armatur/releases/download/v<version>/SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS
```

Verifying a download without rebuilding is described in the [README](README.md#releases).
